# 文字角斗场 YapArena

一款运行于局域网或 Tailscale 私有网络的多人 AI 文字对战游戏。

每位玩家轮流写下一段对局文本，AI 裁判将叙事拆解为可执行效果，服务器再按规则结算为真实的 HP、护盾、持续伤害与出局。最后存活的玩家获胜。

- 支持 2–8 人，推荐 3–6 人；也可加入不同难度的假人。
- 玩家仅需手写对局文本，无需各自准备 API。
- 房主完成一次模型配置后，裁判与困难/炼狱假人共用该模型。
- 内置 3 个扩展包，并支持导入自定义 YAML 扩展包。
- 支持局域网与 Tailscale 组网，不依赖公网服务器。

## 快速开始

### 环境要求

- **Windows 10/11**（一键启动脚本为 Windows 批处理）
- **Python 3.11 或更高版本**（需可通过 `python` 命令调用）
- **Node.js 18 或更高版本及 npm**：用于构建前端；没有 `web/dist` 时必须安装
- 空闲端口：`8000`（游戏）和 `17666`（本机 AI 代理）

### 一键启动（Windows）

1. 双击项目根目录的 `run.bat`。
2. 首次运行时将自动完成以下操作：
   - 创建 `.venv` 虚拟环境；
   - 安装 `server/requirements.txt`；
   - 构建前端；
   - 启动本机 AI 代理（最小化的 `yap-agent` 窗口）；
   - 启动游戏服务器并打开浏览器。
3. 浏览器访问 <http://localhost:8000>。

关闭启动窗口将停止游戏服务器；AI 代理运行于独立的 `yap-agent` 窗口，关闭该窗口即可停止代理。

### 配置 AI

进入首页后，点击右上角的 **「AI 未连接 / AI 待配置 / AI 已连接」** 徽章：

1. 选择服务商，或选择 **自定义（OpenAI 兼容）**；
2. 填写上游地址、模型名和 API Key；
3. 完成 **测试连接** 后再保存。

配置保存在本机的 `agent/config.saved.toml`，不会上传至游戏服务器，也不会进入 Git。支持 OpenAI 兼容的 `/chat/completions` 接口，界面已内置 DeepSeek、OpenAI、Kimi、阿里云百炼、智谱 GLM、硅基流动等预设。

> 未配置 AI 时仍可开局，但仅会执行完整匹配的模板（攻击、治疗、定时护甲、冻结、护甲强化、解除后攻击），复杂对局文本将显示“未执行”。建议先完成模型配置。

### 创建或加入房间

**创建房间（房主）**

1. 在首页切换到“创建房间”；
2. 填写昵称与房间口令（至少 4 位）；
3. 选择扩展包；
4. 进入房间后，将房号或“复制邀请”链接发送给其他玩家；
5. 房主可添加假人并选择假人难度；
6. 所有真人准备后，点击“开始对局”。

**加入房间（玩家）**

1. 打开房主提供的地址，例如 `http://192.168.1.5:8000` 或 Tailscale 地址；
2. 输入昵称、6 位房号和房间口令；
3. 点击“准备”，等待房主开局。

同一台电脑可直接使用 `http://localhost:8000`。其他玩家无法通过你的 `localhost` 访问，需使用启动窗口显示的 **LAN** 或 **Tailscale** 地址。

## 对局流程

1. 轮到你行动时，在输入框中填写一段对局文本，点击“发送”。
2. AI 裁判将结合对局文本、当前 HP、已有属性与持续效果，将其拆解为结构化行动。
3. 服务器完成校验并执行：扣血、回血、护盾、护甲、限制、周期伤害等均会进入战报。
4. 实际结果会同步显示在战报与玩家卡片中。
5. 回合结束后，由下一位存活玩家行动。
6. HP 归零即出局；最后存活的玩家获胜。全员出局时按扩展包配置的平局规则判定（默认依次比较存活回合与 HP 峰值），仍相同则平局。

每回合均设有倒计时；未在时限内发送对局文本，将记为“没来得及动手”。对局文本最多 800 字。

## 机制速览

| 项目 | 当前规则 |
|---|---|
| 生命 | 各扩展包不同，默认 100；每回合开始回复一定 HP |
| 强度 | 随回合增长的强度上限；伤害与治疗受服务器预算约束 |
| 属性 | 默认每人最多 10 个（扩展包可调）；数值与剩余时限公开 |
| 持续效果 | 支持即时、被动、全局/个人行动开始、受伤后、格挡后、被解除时触发 |
| 防御 | 护盾（可限次数/仅挡致命）、固定护甲、百分比减伤 |
| 控制 | 跳过行动、限制可攻击目标；限制仅约束攻击伤害，不限制治疗与辅助 |
| 环境 | 天灾与扩展包事件按包配置结算，不受普通护甲与免伤影响 |
| 继承 | 击杀后继承死者一个正面能力，按包比例折算；冻结、持续扣血、限制等负面或混合能力不继承 |
| 容量 | 新旧能力合计占用每人能力上限；满额时不继承 |
| 胜利 | 最后存活者；全员出局时按包内平局规则比较（默认存活回合、HP 峰值） |

AI 负责理解与提取，实际数值由服务器执行。对于无法支持、存在歧义或审核失败的要求，将明确标记为“未执行”，不会以近似模板替代原始机制。

## 内置扩展包

| 扩展包 | 风格 | 初始 HP | 每回合回复 | 天灾起始 |
|---|---|---:|---:|---:|
| **无名角斗场**（默认） | 数值基线，节奏均衡 | 100 | 5 | 第 15 回合 |
| **霓虹废土** | 高烈度快节奏，伤害和天灾更早 | 80 | 3 | 第 12 回合 |
| **修真乱斗** | 慢热高血量，后期天罚收束 | 140 | 8 | 第 18 回合 |

每个扩展包均包含独立的强度曲线、属性上限、天灾曲线、特殊事件与裁判世界观。创建房间时可切换扩展包。

## 扩展包

### 导入扩展包

创建房间时，房主可在本机导入 `.yaml` / `.yml` 文件：

- 文件必须是 UTF-8，最大 200 KB；
- 导入前会完整校验，字段错误将指出具体位置；
- 相同 ID 的扩展包将提示是否覆盖；
- 已开局的房间将继续使用开局时的扩展包，不受热加载影响。

用户包默认存放在：

- Windows：`%USERPROFILE%\.yap-arena\packs`
- macOS / Linux：`~/.yap-arena/packs`

也可通过环境变量 `YAP_PACKS_DIR` 指定其他目录。

### 开发者面板

首页的“开发者：编辑扩展包”入口仅允许本机访问，支持：

- 查看字段速查与最小模板；
- 校验 YAML；
- 由 AI 起草完整扩展包；
- 校验通过后保存至用户扩展包目录并热加载。

内置扩展包的 YAML 可直接作为编写参考。

## AI 与隐私

- **模型提供方**：房主。裁判、环境事件以及困难/炼狱假人均使用房主本机代理配置的模型。
- **玩家的 API 要求**：玩家无需配置 API，仅负责填写对局文本；模型调用发生在房主设备上。
- **密钥存储位置**：默认位于 `agent/config.saved.toml`，仅保存在本机；也可通过 `agent/config.toml` 的 `key_env` / `key_file` 配置。
- **密钥传输范围**：密钥不会上传至游戏服务器。游戏服务器仅访问本机代理，由代理访问已配置的上游模型。
- **端口安全**：`17666` 为 AI 代理端口，仅应在本机或可信网络中使用；请勿将 `8000` 或 `17666` 直接暴露至公网。
- **玩家数据**：房间、玩家与战报均保存在内存中，服务重启后清空，不使用数据库。
- **调试日志**：默认写入 `logs/judge_debug.jsonl`，内容可能包含对局文本与裁判计划。在共享设备上使用或发布前，可设置 `YAP_DEBUG_LOG=0` 关闭。

建议仅在局域网或 Tailscale 内使用，不要将游戏端口直接映射至公网。
