## 3. 关键实现细节

### 3.1 击杀继承（inheritance.py）

```
裁定结算导致 target.hp = 0
  → 记 death 事件（killer = 本次宣言的发动者）
  → 若 killer 存活且不是死者本人（排除自伤 / 中毒 / 天灾）：
      取死者当前 value 最高的属性（同分取 cap 大者）
      新 initial = round(victim.value × power_ratio)，下限 1
      新 cap     = round(victim.cap × power_ratio)，下限 initial
      name = 原外壳名 + "·遗"（超长截断；重名追加序号）
      作为新账户封存进凶手账户（占 max_count 名额）
  → 账本 type=inheritance（公开：谁继承了哪件外壳及折算前后数值）
  → 广播 inheritance；属性数值对新主人单播
```

- 自动继承，不做「凶手 30s 选择/改名」交互（当前状态机没有回应窗口，避免新增阶段）。
- 满额、死者无属性、killer 已死、killer 即本人 → 不继承，不报错。
- 天灾致死 `killer=null`，天然不触发继承。

### 3.2 天灾（disaster.py）

```
每回合开始（回复结算之后、周期效果之前）：
  level  = turn_no < start_turn ? 0 : (turn_no − start_turn) // every_n_turns + 1
  damage = base_damage + growth × (level − 1)
  → 所有存活玩家 HP −damage（直接扣血，不经裁判、无视护甲与免伤）
  → 账本 type=disaster + 广播 disaster {level, damage, changes}
  → HP 归零者出局（killer=null，不触发继承）
  → 若全场死光，按 tie_break（存活回合数 → HP 峰值）结算
```

- 数值完全由服务端硬结算，裁判不参与（避免每回合调模型）。
- 叙述使用固定模板：「第 N 回合，天灾降临：竞技场的天空渗出血色，全场承受 X 点侵蚀」；等级提升时追加一句。
- 设计意图：杜绝全员龟缩，给残血玩家制造最后窗口。

### 3.3 扩展包系统完整版

- 包注册表：启动扫描 builtin + 用户目录；房间创建时房主选包，进入对局后锁死。
- 校验错误模板：`包 xxx 的 hp.base 应为正整数，收到 "abc"（字段路径：hp.base）`——逐字段报错，一次全量列出。
- 安全校验沿用：`path.relative` 防穿越、YAML 大小上限 200KB、仅 UTF-8。
- 包编写指南（README 章节）：字段表 + 最小可运行示例 + 三条曲线调参建议（回合长度 ↔ cap_growth；开局死亡率 ↔ hp.regen；收束速度 ↔ disaster 参数）。

## 8. 风险与规避

| 风险 | 规避 |
|---|---|
| 继承数值失衡（外壳强数值跟随放大） | 折算比例走包参数；只降不升 |
| 天灾过早/过晚破坏节奏 | start_turn / every_n_turns / base_damage / growth 全部走包参数，按自动局实测调 |
| 天灾与免伤属性冲突引发争议 | 明确定义为环境伤害，绕过护甲与免伤，叙事上写清「天灾无视一切防护」 |
| 三包内容工作量失控 | 每包只做差异化必需项（曲线+referee_prompt+程度词表），其余字段共享 default |
| UI 打磨吞噬工期 | 打磨任务列明「必做/可弃」两档，可弃项可顺延到发布后迭代 |
