> **已裁撤（2026-11 需求方确认）**：上诉系统、幽灵系统、战报导出不再开发。
> 理由：属性数值已对全场透明，幽灵"全知视角"失去意义；上诉与战报对当前单人+假人玩法收益过低。
> PRD 中对应章节仅作历史设计保留。

> **当前优先约定（2026-11-18）**：以已落地实现和需求方最新确认为准，不按滞后的 P2 描述回退机制。继承适配新旧能力，任何负面效果均不继承；UI 优化暂停，发布准备留存待后续处理。本轮只调整继承和假人模板衔接，通用效果说明见 [EFFECT-ENGINE.md](EFFECT-ENGINE.md)。

> **本阶段主线是「把游戏的性格做出来」**：继承制造戏剧钩子，天灾收束战局，扩展包打开社区生态。引擎在 P0/P1 已定型，本阶段原则上不动核心管线，只做编排层与生态层。

## 1. 范围

### 范围内

- 击杀继承：死亡时凶手自动继承死者一个属性外壳，按包比例重新折算并封存为新账户
- 天灾曲线生效（引擎硬结算 + 模板叙述 + UI 等级显示）
- 特殊事件：扩展包可定义回合级事件（触发条件 / 目标 / 伤害 / 属性模板），引擎硬结算
- 扩展包系统完整版：多包加载、房间选包、包校验与友好报错、包编写指南
- 内置包扩充至 3 个
- UI 打磨与视觉基调落地
- 开源发布准备：README、演示、仓库清理

### 范围外

- 新的数值公式或核心状态机变更（如需调整，走包参数，不改引擎）
- 观战位（PRD §13 待决 #5，本阶段不做，除非需求方拍板）
- 移动端深度适配
- 国际化（界面仅中文；包内容天然任意语言）

## 3. 关键实现细节

### 3.1 击杀继承（inheritance.py）

```
实际伤害结算导致 target.hp = 0
  → 通用运行时在死亡清理前保存正面能力候选
  → 记 death 事件（killer = 实际伤害来源；周期/连锁保留创建者归属）
  → 若 killer 存活且不是死者本人：
      在符合条件的旧属性与通用正面效果中取强度最高的一个（同分取 cap 大者）
      旧属性沿用外壳折算：
      新 initial = round(victim.value × power_ratio)，下限 1
      新 cap     = round(victim.cap × power_ratio)，下限 initial
      name = 原外壳名 + "·遗"（超长截断；重名追加序号）
      作为新账户封存进凶手账户（占 max_count 名额）
  → 账本 type=inheritance（公开：谁继承了哪件外壳及折算前后数值）
      通用效果保留机制，数值/剩余格挡次数按比例折算，时限不重置
  → 广播 inheritance；实际能力与状态通过快照公开同步
```

- 自动继承，不做「凶手 30s 选择/改名」交互（当前状态机没有回应窗口，避免新增阶段）。
- 满额、死者无属性、killer 已死、killer 即本人 → 不继承，不报错。
- 天灾致死 `killer=null`，天然不触发继承。
- 冻结、周期扣血、攻击目标限制、吸取、伤害、解除他人能力等负面或无法独立判定为正面的能力不进入继承候选；正负混合能力整体排除，不提取其中好处。
- 可继承的通用机制包括护甲、减伤、护盾和定时/受伤后/格挡后治疗。只转移死者的受益份额；自身条件、触发对象和个人时钟改绑继承者，依赖其他玩家或其他效果的能力不猜测转移。
- 强度排序：旧属性用当前 value/cap；通用效果用数值动作量与剩余格挡次数之和，无限格挡按1计入排序（只是候选排序，不是战斗强度等价换算）。同分稳定保留先出现者。折算取整、正数下限1；无次数限制的护盾不凭空增加次数限制。
- 通用能力保留剩余时限和轮转进度、仅致命/不可解除等原规则；耗尽的格挡不恢复。继承者已满足结束条件则不授予，不把效果变成永久能力。
- 旧属性继续只继承外壳，不复制 shield 等状态标记；冻结/负向 per_turn 的整个旧属性在选择阶段已排除。新旧能力合计占用每人容量，通用效果还受全局容量限制。

### 3.2 天灾（disaster.py）

```
每回合开始（回复结算之后、周期效果之前）：
  level  = turn_no < start_turn ? 0 : (turn_no − start_turn) // every_n_turns + 1
  damage = base_damage + growth × (level − 1)
  → 所有存活玩家 HP −damage（直接扣血，不经裁判、无视护甲与免伤）
  → 账本 type=disaster + 广播 disaster {level, damage, changes}
  → HP 归零者出局（killer=null，不触发继承）
  → 若全场死光，按 tie_break（存活回合数 → HP 峰值）结算
```

- 数值完全由服务端硬结算，裁判不参与（避免每回合调模型）。
- 叙述使用固定模板：「第 N 回合，天灾降临：竞技场的天空渗出血色，全场承受 X 点侵蚀」；等级提升时追加一句。
- 设计意图：杜绝全员龟缩，给残血玩家制造最后窗口。

### 3.3 扩展包系统完整版（已实现）

- 包注册表 `PackRegistry`：启动扫描 `server/packs/builtin/*.yaml` 与用户目录（默认 `~/.yap-arena/packs`，可用 `YAP_PACKS_DIR` 覆盖）。
- 同 id 的用户包覆盖内置包，方便本地改造；其余合法包不受影响。
- 房间创建时传入 `pack_id` 选包，房间创建后包对象固定，进局锁死；未传或未知 id 时分别回落到默认包 / 返回 `PACK_NOT_FOUND`。
- 校验：`Pack` 逐字段 Pydantic 校验，一次列出全部错误；错误信息带中文字段名与字段路径（如 `「初始血量」（hp.base）：不能小于 10；当前值 5`）。
- 安全校验沿用：`Path.relative_to` 防穿越（白名单：`server/packs` 与用户包目录）、YAML 大小上限 200KB、仅 UTF-8。
- 热加载：`GET /api/packs` 会比对目录 mtime/size 自动重扫；也可 `POST /api/packs/reload` 强制重扫。已开局的房间仍持有旧包对象，不受影响。
- 失败容错：某个包校验失败只跳过该包，其余照常可玩；失败原因随 `/api/packs` 的 `issues` 返回，建房页会提示。
- 包编写指南（README 章节，P2-T6）：字段表 + 最小可运行示例 + 三条曲线调参建议（回合长度 ↔ cap_growth；开局死亡率 ↔ hp.regen；收束速度 ↔ disaster 参数）。

### 3.4 特殊事件（events.py）

```
每回合开始（天灾之后、周期效果之前）：
  逐条遍历 pack.events：
    should_fire？ ← start_turn / turns / every / chance / cooldown / max_times
      → pick_targets：all | random | lowest_hp | highest_hp | lowest_ratio | highest_ratio（同分随机）
      → 结算 hp（固定值 + 最大生命百分比，正数回血）→ 记录本回合触发次数与回合
      → 若配置 attribute：按模板授予属性（受 max_count 与重名限制，满额则跳过）
      → 账本 type=event + 广播 special_event {event_id, name, narrative, effects}
  → HP 归零者出局（killer=null，不触发继承）
```

- 触发限制全部可选：`turns` 指定回合列表、`every` + `start_turn` 周期触发；`chance` 概率、`cooldown` 冷却、`max_times` 次数上限。
- `cooldown: N` 表示两次触发至少间隔 N+1 个回合；`max_times: 0` 表示不限次数。
- 文案支持 `{target}`（受影响玩家名）与 `{name}`（事件名），未配置时使用默认句。
- 事件与天灾一样属于环境结算，不经裁判、无视护甲与免伤；这是扩展包作者的主要玩法扩展点（沙暴、电网过载、灵气潮汐、黑市交易等）。
- 单个包最多 12 个事件，`id` 必须唯一。

**judged 模式（`mode: judged`）**

- 事件触发时，把 `judge_prompt` + 目标玩家拼成一次环境裁定，送进裁判 AI 管线；
- 复用现有数值钳制、属性增删改校验、重试与降级、账本广播；
- 服务端会额外告诉裁判这是环境事件：`hp_delta` 直接生效，不再套护甲/免伤；裁判可以自行把伤害写成 0 来体现能力抵挡；
- `hp / hp_pct / attribute` 在 judged 事件里作为 **AI 不可用时的兜底固定效果**，因此离线也能玩；
- 成本：每次触发多一次模型调用。事件本身低频，建议 judged 事件控制在每局 1~3 次。

### 3.5 扩展开发者面板（DevPanel）

- 入口：首页「开发者：编辑扩展包」，仅本机访问（`127.0.0.1 / ::1 / localhost`），局域网玩家调用会得到「只允许本机访问」。
- 能力：
  - `GET /api/dev/schema`：返回最小可运行模板 + 字段速查；
  - `POST /api/dev/validate`：对 YAML 文本做与加载器完全一致的校验，返回逐字段人话错误；
  - `POST /api/dev/draft`：把世界观设想交给本机代理生成整包 YAML 草稿（可携带 `base_url`），服务端再校验一遍；
  - `POST /api/dev/save`：校验通过后写入用户包目录 `<id>.yaml` 并触发热加载，立即出现在建房列表。
- 保存只写用户目录，不会覆盖内置包；同 id 时按既有规则覆盖（可用于本地改造内置包）。
- 面板内数据不落库，关闭即丢弃；编辑器只是普通 textarea。

### 3.6 假人 AI 与 API 归属（P2-T9）

- **所有模型调用统一使用服务器/房主的本机代理**：裁判、`mode: judged` 事件、世界摘要、困难/炼狱假人、开发者面板共用同一份 key 与模型。
- 真人玩家只手写宣言，**不需要配置自己的 API**，也不做「未配置 API 不能准备」的门禁。
- 困难/炼狱假人：每个假人回合调用一次 `draft_bot_action`，提示词包含本人 HP/属性、场上状态、近期账本、世界史、本回合强度上限和建议目标。
- 预算：`max(5s, min(18s, declare_s - 12s))`；超时、agent 未连接、空输出都回落到 `bots.py` 的确定性模板。
- 简单/普通假人完全不调用模型（保持模板，省成本、稳定）。
- 开关：`YAP_BOT_AI=0` 关闭假人 AI；自动对局默认同时关闭 `YAP_JUDGE_AI` 与 `YAP_BOT_AI`。
- 风险控制：模型返回后引擎会再次校验回合与行动者，迟到的结果直接丢弃，不会污染下一阶段。
- 模板改为完整可执行的攻击、治疗、定时护甲、冻结、护甲强化和显式解除后攻击；旧的含糊“凝聚装备强度/强化到某值”不再由假人生成。困难/炼狱的 AI 发言策略保持。
- 模板读取通用效果和旧属性，识别既有防御、冻结、受保护状态及合计容量，遵守实际攻击对象限制；强化使用真实效果 ID，不重置时限。离线仅完整匹配已定义模板，其他自由文本仍明确未执行。

## 4. 协议增量（相对 P1）

### 后续修复：扩展包导入与先手规则

- 建房页支持选择 UTF-8 `.yaml` / `.yml` 文件（不超过 256 KB），调用本机限定的 `POST /api/packs/import`。先完整校验，同 id 须确认覆盖；成功后热加载、刷新列表并自动选中。运行中的房间继续使用开局时的包。
- 属性悬浮提示由实际效果字段生成，不显示属性来历或模型叙事。
- 旧独立 `duels` 模型已移除，改为快照中的 `active_effects`；目标限制、时间单位、结束血量条件和不可提前解除分别表达。满足结束条件后解除，随后回血不重新激活。
- 裁判和假人读取实际通用效果。攻击限制只约束伤害，不禁止第三方治疗或辅助；多个限制取交集，冻结仍优先。未声明的保护和禁止改换对手不自动附加。
- 不可破坏的禁锢不能被持有者自删或第三人转移；不可破坏免伤不能被 `pierce` 绕过。先手约束优先于后手宣言，裁判不得将历史修辞视为已成立能力。
- 宣言经过结构提取、确定性检查、独立语义审核和通用运行时。无法表达或审核失败的要求明确不执行，新增机制仍需对应的数据结构和结算逻辑。

| 方向 | type | payload |
|---|---|---|
| S→C | `disaster` | `{level, damage, changes[{player_id, delta, hp, dead}], turn_no}` |
| S→C | `special_event` | `{event_id, name, narrative, effects[{player_id, name, delta, hp, dead, attribute}], turn_no}` |
| S→C | `inheritance` | `{killer, killer_name, victim, victim_name, name, source_name, source_value, value}` |

事件类型使用既有 `disaster / event / inheritance`（`LedgerType` 已定义）。

`special_event` 在 judged 模式下额外携带 `source: "ai"`；AI 不可用时回落到固定结算，事件账本不带 `source`。

## 8. 风险与规避

| 风险 | 规避 |
|---|---|
| 继承数值失衡（外壳强数值跟随放大） | 折算比例走包参数；只降不升 |
| 天灾过早/过晚破坏节奏 | start_turn / every_n_turns / base_damage / growth 全部走包参数，按自动局实测调 |
| 天灾与免伤属性冲突引发争议 | 明确定义为环境伤害，绕过护甲与免伤，叙事上写清「天灾无视一切防护」 |
| 三包内容工作量失控 | 每包只做差异化必需项（曲线+referee_prompt+程度词表），其余字段共享 default |
| judged 事件成本失控 / AI 判得过狠 | 事件本身低频；数值仍走钳制；`hp/attribute` 始终保留为离线兜底，必要时把 judged 事件降级成 fixed |
| 开发者面板被局域网友改写包 | 所有 `/api/dev/*` 仅接受回环地址；保存只写用户包目录 |
| UI 打磨吞噬工期 | 打磨任务列明「必做/可弃」两档，可弃项可顺延到发布后迭代 |
